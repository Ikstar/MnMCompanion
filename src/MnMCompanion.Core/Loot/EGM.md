# Loot

## Overview
Implements loot extraction, group purse-split estimation, multi-character merging, session boundary persistence, vendor item valuation, Wilson-interval monster drop rates, cross-day item search, and clipboard/archive text breakdowns (`namespace MnMCompanion.Loot`). Coordinates thread-safe incremental ledger refreshes via `LootStore` while keeping all analytics and pricing models pure in memory.

## Invariants
- Concurrency and snapshot isolation: `LootStore` serializes state mutations (`UsePublicPrices`, `DetectPlayed`, `ChangeRoot`, `Select`, `Refresh`, `NewJoins`) under `lock (_gate)` and publishes immutable snapshots to a `volatile` field so `Days()`, `Events()`, `Values`, and `Version` read lock-free (`RescanSources()` assigns `Sources` outside `_gate`; `LootSessions` guards its own state with an internal `lock`).
- Selection and refresh lifecycle: `Select(...)` and `ChangeRoot(...)` clear the active snapshot until `Refresh()` runs; `UsePublicPrices(...)` sets `_pricesChanged = true` and defers rebuilding `ItemValues` until the next `Refresh()`. `NewJoins()` requires single-character selection (`Selected != null`), primes its watermark returning `[]` on the first call after `Select()`, and ignores joins older than `JoinFreshness` (`30m`).
- Ledger extraction and split estimation: `LootExtractor.Extract` reads `act_13` (`Count >= 1`, non-empty `d04`) and `act_14` (packed `d12 > 0`, ignoring `d11`), drops rows with empty `Actor`, deduplicates `Social` owner rows against `Character` rows within `2s`, maps blank, `"party_split"`, or `"npc_corpse"` `d13`/`Name` coin sources (`PurseSource` returning `""`, including apostrophe-truncated nameless coin rows) to `UnknownCreature`, and rewrites self-looted unshared purses during active party windows (`GroupSplits.InGroup`) with estimated shares (`Estimated: true`).
- Multi-character merge and session bounds: `LootStore.Refresh` merges multiple selected characters via `LootMerge.Combine` only within the same server (taking max per-ledger duplicate count rather than summing across party ledgers). `LootSessions.All` always forms `Marks.Count + 1` contiguous `[Start, End)` intervals; `LootSessions.Start` enforces `>= 5s` (`MinGap`) relative to the last mark, whereas `LootSessions.Load` preserves and chronologically sorts persisted marks without filtering by `MinGap`.
- Valuation precedence and throttling: `ItemValues.Of` resolves prices strictly in order `Sold > Public > Charged > Estimated (3-word then 2-word family median) > None`. `LootStore.Refresh` rescans all local characters' top-level `Character` files (`characterFilesOnly: true`) on disk at most once per `30s` (or when `_prices` is empty); `UsePublicPrices` rebuilds `ItemValues.FromLedger` from already-cached `_prices` rows without bypassing the `30s` disk rescan throttle. Depends only on `MnMCompanion.Ledger` and .NET BCL.

## Side Effects
- Read-only game ledger I/O via `LedgerLocator` and `LedgerFolder` during `LootStore` construction, source scanning, and `Refresh()`.
- App-state persistence: `LootSessions` reads `<folder>/sessions.json` (catching `IOException`, `UnauthorizedAccessException`, and `JsonException`) and atomically writes `<folder>/sessions.json` via `sessions.json.tmp` move (catching `IOException` and `UnauthorizedAccessException`); `LootStore.NewSession` writes formatted session archive files directly via `File.WriteAllText` under `<StateFolder>/sessions/<yyyy-MM-dd HHmm>-<HHmm>.txt` (catching `IOException` and `UnauthorizedAccessException`).
- In-memory mutations on `LootStore` and `LootSessions`, plus fallback clock reads (`DateTime.UtcNow` in `LootStore.Refresh`, `DateTime.Now` in `LootStore.NewSession`/`NewJoins`); all extraction, split-inference, merge, breakdown, valuation, drop-rate, search, and zone types are pure in-memory with zero network calls.
