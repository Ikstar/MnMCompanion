# Timers

## Overview
Manages user countdown presets, active timers, monster corpse timers, Win32 global hotkey validation, overlay opacity/click-through settings, and alert sound specifiers (`namespace MnMCompanion.Timers`). Persists timer definitions and running expirations to `timers.json` while keeping Win32 P/Invoke and audio playback outside Core.

## Interface

- Hotkeys, overlay appearance, click-through, and sounds ([Hotkey.cs](./Hotkey.cs), [TimerLook.cs](./TimerLook.cs), [ClickThroughKey.cs](./ClickThroughKey.cs), [TimerSounds.cs](./TimerSounds.cs)):

## Invariants
- Sanitized unique names and bounds: Timer names strip control chars, trim whitespace, cap length at `40` (`MaxName`), and enforce `OrdinalIgnoreCase` uniqueness across `TimerBook.Presets` (`<= 100`) and `TimerBook.Running` (`<= 50`) when mutated via `TimerBook` methods; durations must be in `[1, 86400]` seconds (`24h`).
- Safe global hotkeys: Supported keys are `A–Z`, `0–9`, `F1–F24`, and numpad keys (`Num0–Num9`, `NumAdd`, `NumSubtract`, `NumMultiply`, `NumDivide`, `NumDecimal`); alphanumeric keys require `Ctrl`, `Alt`, or `Win` (`None` or `Shift`-only is rejected so typing in game/chat is never intercepted), and canonical hotkey strings must be unique (`Ordinal`) across `Presets` (conflicting/invalid keys load as `Key = null`).
- UTC vs local clock separation and grace window: `TimerBook` and `RunningTimer.EndsUtc` strictly use UTC timestamps, whereas `CorpseTimers.Active` and `CorpseTimer.EndsLocal` use local `DateTime` matching `MnMCompanion.Loot.LootedCorpse.Start`. Expired timers remain visible for `DoneShownSeconds` (`15s`) before `Prune` or `Active` drops them.
- Overlay and sound normalization: Background opacity clamps to `[5, 100]%` so layered windows never reach unclickable `0%` alpha, and title-bar alpha never drops below `0xB0`; sound specifiers normalize strictly to `null`, `system:<Beep|Asterisk|Exclamation|Hand|Question>`, or `file:<.wav path>` (`<= 260` non-control chars). `TimerSounds.WindowsFiles` excludes `*.wav` basenames starting with `"Speech"` (case-insensitive) and classifies results into `"Alarms"` (`Alarm*`), `"Rings"` (`Ring*`), and `"Windows sounds"`, ordered by group then case-insensitive name.
- Concurrency and dependencies: `TimerBook` and `CorpseTimerSetting` are mutable and unsynchronized, while all static helper classes are stateless and thread-safe. Depends only on `MnMCompanion.Loot.LootedCorpse` and .NET BCL.

## Side Effects
- Synchronous disk read and atomic `.tmp`-move write of `<folder>/timers.json` in `TimerBook.Load` and `TimerBook.Save`: both short-circuit without disk I/O when `folder is null` (`Load` returns an empty `TimerBook`; `Save` returns `false`); `Load` catches `IOException`, `UnauthorizedAccessException`, and `JsonException`, whereas `Save` catches `IOException` and `UnauthorizedAccessException`.
- Read-only enumeration of top-level `*.wav` files in the Windows Media folder via `TimerSounds.WindowsFiles` (querying `Environment.SpecialFolder.Windows` when `folder` is `null`, excluding `"Speech*"` files, and catching `IOException` and `UnauthorizedAccessException` to return `[]`).
- In-memory list mutations on `TimerBook.Presets` and `TimerBook.Running`; zero Win32 P/Invoke, audio playback, network calls, or locks.
