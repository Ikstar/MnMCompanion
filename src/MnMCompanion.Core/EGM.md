# MnMCompanion.Core

## Overview
Platform-independent domain, parsing, analytics, and local-cache library ([MnMCompanion.Core.csproj](./MnMCompanion.Core.csproj), `TargetFramework = net10.0`, `RootNamespace = MnMCompanion`) powering the Monsters & Memories companion application and CLI/tests. Resolves and migrates the local application data directory via `AppFolder` ([AppFolder.cs](./AppFolder.cs)), computes per-window UI scale presets and monitor work-area bounds via `UiScale` ([UiScale.cs](./UiScale.cs)), enforces detachable-tab docking and compact-view invariants via `TabDockPolicy` ([TabDockPolicy.cs](./TabDockPolicy.cs)), and encapsulates all ledger ingestion, loot/history analytics, journal scrubbing, community contribution building, auction market math, recipe indexing, and timer rules without external NuGet packages, databases, network transports, or Windows UI dependencies.

## Interface
- Project definition: [MnMCompanion.Core.csproj](./MnMCompanion.Core.csproj) (`Microsoft.NET.Sdk`, `net10.0`, `Nullable = enable`, `ImplicitUsings = enable`, `RootNamespace = MnMCompanion`).
- `AppFolder` (`public static class` in [AppFolder.cs](./AppFolder.cs)): Resolves and migrates the application's local state directory:
  - `Name = "MnMCompanion"`, `PreviousName = "LootWindow"`, `OverrideVariable = "MNMCOMPANION_DATA"` (`public const string`s)
  - `Folder` (`public static string { get; }`): Thread-safe `Lazy<string>`-cached process-wide data directory path.
  - `Choose(string? overrideFolder, string localAppData) -> string`: Returns `Path.GetFullPath(overrideFolder.Trim())` when `overrideFolder` is non-whitespace, otherwise delegates to `Resolve(localAppData)`.
  - `Resolve(string localAppData) -> string`: Resolves `<localAppData>/MnMCompanion`, migrating `<localAppData>/LootWindow` via `Directory.Move` when only `LootWindow` exists, or falling back to `LootWindow` if locked.
- `WorkArea`, `WindowBox`, & `UiScale` (`public readonly record struct`s and `public static class` in [UiScale.cs](./UiScale.cs), `namespace MnMCompanion`): Pure-BCL window scale presets and monitor work-area geometry:
  - `WorkArea(double Left, double Top, double Width, double Height)` with `double Right => Left + Width` and `double Bottom => Top + Height`.
  - `WindowBox(double Left, double Top, double Width, double Height, double MinWidth, double MinHeight)`.
  - `Presets = [100, 125, 150, 175, 200]` (`public static readonly IReadOnlyList<int>`), `Default = 100`, `Min = 100`, `Max = 200` (`public const int`s).
  - `Clamp(int percent) -> int`, `Nearest(int percent) -> int`, `Next(int current) -> int`, `Previous(int current) -> int`, `Factor(int percent) -> double`.
  - `ClampToWorkArea(double left, double top, double width, double height, double baseMinWidth, double baseMinHeight, int scalePercent, WorkArea work) -> WindowBox`.
  - `ResizeForScale(double left, double top, double width, double height, double baseMinWidth, double baseMinHeight, int oldScalePercent, int newScalePercent, WorkArea work) -> WindowBox`.
- `TabSlot`, `NormalizedTabs`, & `TabDockPolicy` (`public sealed record`s and `public static class` in [TabDockPolicy.cs](./TabDockPolicy.cs), `namespace MnMCompanion`): Canonical page ordering, `>= 1` docked-tab rule, and compact-view eligibility:
  - `TabSlot(string Name, bool Open, int Scale, bool OnTop, bool Compact)` and `NormalizedTabs(string ActiveDockedPage, IReadOnlyDictionary<string, TabSlot> Tabs)`.
  - `PageNames = ["Map", "Loot", "Vendor", "Trades", "Items", "Harvest", "Recipes", "Market"]` and `CompactPages = ["Loot", "Vendor", "Items", "Harvest"]` (`public static readonly IReadOnlyList<string>`s).
  - `IsKnownPage(string? name, out string canonical) -> bool`, `SupportsCompact(string? pageName) -> bool`, `CanDetach(int dockedCount) -> bool`.
  - `DockedPages(IReadOnlyDictionary<string, TabSlot> tabs) -> IReadOnlyList<string>`, `NextDockedPage(IReadOnlyList<string> dockedBeforeDetach, string detachingPage) -> string`, `Normalize(string? miniPage, IReadOnlyDictionary<string, TabSlot>? raw) -> NormalizedTabs`.
- Child subsystem contracts:
  - [Community](./Community/EGM.md): Opt-in consent policy, schema-4 anonymized contribution builder, SHA-256 fingerprinting, and upload cadence (`MnMCompanion.Community`).
  - [History](./History/EGM.md): Vendor, harvest, trade, and item-movement ledger models, scoping/period filters, and statistical summaries (`MnMCompanion.History`).
  - [Journal](./Journal/EGM.md): NPC dialogue log parser and whole-word player-name privacy scrubber (`MnMCompanion.Journal`).
  - [Ledger](./Ledger/EGM.md): Windows/Wine game folder discovery, incremental JSON ledger reader/deduplicator, base64/coin decoders, and active-character watcher (`MnMCompanion.Ledger`).
  - [Loot](./Loot/EGM.md): Thread-safe `LootStore`, group split estimation, multi-character merge, session persistence, item valuation, Wilson drop rates, search, and breakdowns (`MnMCompanion.Loot`).
  - [Market](./Market/EGM.md): Persistent auction price book (`market.json`), `mnm-db.com` feed parser, item classification, standing price math, and refresh throttling (`MnMCompanion.Market`).
  - [Recipes](./Recipes/EGM.md): Wiki tradeskill recipe parser, local cache (`recipes.json`), level banding, multi-token/range search, and refresh throttling (`MnMCompanion.Recipes`).
  - [Timers](./Timers/EGM.md): Countdown timer book (`timers.json`), monster corpse timers, global hotkey validation, overlay opacity/click-through rules, and sound specifiers (`MnMCompanion.Timers`).

## Invariants
- Pure .NET BCL and zero external dependencies: Targets `net10.0` (`Nullable = enable`, `ImplicitUsings = enable`) with zero NuGet `PackageReference` entries and zero `ProjectReference` entries, allowing cross-platform execution and testing on Linux and Windows.
- Zero SQLite, zero network, and zero UI/Win32 boundary: Contains no SQLite or database engine (all local caches are plain JSON/text files), performs zero HTTP/socket calls (remote feeds and uploads are passed in/out as JSON strings with pure rate-limit plans), and has zero WPF, WinForms, audio playback, or Win32 P/Invoke dependencies.
- Read-only game data guarantee: Game installation folders, Wine/Proton prefixes, and game JSON ledger files are strictly read-only (`FileShare.ReadWrite | FileShare.Delete`); Core never creates, modifies, or deletes files inside game directories.
- Test/screenshot storage isolation: `AppFolder.Folder` passes `Environment.GetEnvironmentVariable("MNMCOMPANION_DATA")` and `Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData)` to `AppFolder.Choose`; when `MNMCOMPANION_DATA` is non-whitespace, `Choose` returns `Path.GetFullPath(overrideFolder.Trim())` directly and skips `AppFolder.Resolve(localAppData)` (avoiding `Directory.Exists` checks and `Directory.Move` migration in `localAppData`) so tests and headless runs never read or mutate a user's live data folder.
- Safe legacy folder migration: `AppFolder.Resolve` renames `<localAppData>/LootWindow` to `<localAppData>/MnMCompanion` only when `MnMCompanion` is absent and `LootWindow` exists; if `Directory.Move` fails with `IOException` or `UnauthorizedAccessException` (e.g., another instance holds open files), it falls back to `LootWindow` rather than throwing or creating an empty split-brain directory. `AppFolder.Folder` caches the result once per process via thread-safe `Lazy<string>`.
- Window scale snapping and work-area clamping (`UiScale`): `Clamp` bounds inputs to `[100, 200]`; `Nearest` snaps `Clamp(percent)` to `Presets` (`[100, 125, 150, 175, 200]`), breaking midpoint ties toward the smaller preset; `Next` and `Previous` step one preset from `Nearest(current)` saturating at `200` and `100`; and `Factor(percent)` returns `Nearest(percent) / 100.0`. `ClampToWorkArea` caps scaled minimums at `(work.Width, work.Height)`, clamps `(w, h)` to `[minW..work.Width, minH..work.Height]`, and clamps `(l, t)` to `[work.Left..Math.Max(work.Left, work.Right - w), work.Top..Math.Max(work.Top, work.Bottom - h)]` so the entire window and right-aligned title-bar controls remain inside `work` (including negative secondary-monitor DIP coordinates); `ResizeForScale` multiplies `width` and `height` by `Factor(newScalePercent) / Factor(oldScalePercent)` while keeping `(left, top)` before delegating to `ClampToWorkArea`.
- Canonical tab docking and normalization (`TabDockPolicy`): `CanDetach(dockedCount)` requires `dockedCount > 1` so `PanelWindow` retains `>= 1` docked tab; `DockedPages` treats absent `PageNames` keys in sparse dictionaries as docked (`!Open`) in canonical `PageNames` order (with case-insensitive lookup preferring `Open == true`); and `NextDockedPage` returns the next item in `dockedBeforeDetach`, else the preceding item when detaching the last entry, else the first other page or `"Loot"`. `Normalize` keeps `Tabs` sparse, strips null/unknown keys (`IsKnownPage`), canonicalizes `Name` casing, resolves case-insensitive duplicates in `StringComparer.Ordinal` order while preferring `Open == true` over closed entries, snaps `Scale` via `UiScale.Nearest`, clears `Compact = false` outside `CompactPages`, force-docks `preferred` (`IsKnownPage(miniPage)` else `"Loot"`) by setting only `Open = false` (preserving `Scale`, `OnTop`, and `Compact`) when all 8 `PageNames` are `Open`, and sets `ActiveDockedPage` to `preferred` if docked else `docked[0]`.

## Side Effects
- `AppFolder.Folder` (on first read) eagerly queries `Environment.GetEnvironmentVariable("MNMCOMPANION_DATA")` and `Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData)`; only when `MNMCOMPANION_DATA` is null or whitespace does it invoke `Resolve(localAppData)`, checking `Directory.Exists` and potentially executing a one-time `Directory.Move` from `LootWindow` to `MnMCompanion`.
- Root helpers and child subsystem I/O boundaries: `UiScale`, `TabDockPolicy`, `Community`, `History`, and `Journal` are pure in-memory with zero disk I/O; `Ledger` performs read-only game directory, Wine prefix, and JSON ledger reads; `Loot`, `Market`, `Recipes`, and `Timers` read and atomically write (`*.tmp` staging + `File.Move`) local JSON state under `AppFolder.Folder` or caller-provided state folders, while `LootStore.NewSession` writes `<StateFolder>/sessions/*.txt` breakdown archives directly via `File.WriteAllText` (and `Timers` also performs read-only Windows Media `.wav` enumeration).
- Performs zero network I/O, zero database I/O, zero registry writes, and zero mutations outside the application's own state directory.
